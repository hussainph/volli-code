### Goals

*Retained as written because the decision log cites them by number ("goal 2", "goal 3"). Also agent-drafted — revise freely once the sections above are yours.*

1. Merge planning, organization, and execution in one place — track ticket progress and execution/branching/PRs together.
2. Build an auditable per-project history of all agent sessions and decisions.
3. Mirror the lifecycle of AI-engineered projects to CI/CD best practices (ticket → branch → PR).
4. Expose coding agents to the planning layer without a bulky MCP.
5. Massively increase parallel session throughput via neat organization (dozens of sessions across projects).
6. Make the human a powerful orchestrator: plan and execute across multiple projects concurrently, solo or with agents.

The following were resolved in a design review (July 2026), closing the questions originally parked below:

| # | Decision | Alternatives rejected | Rationale |
|---|----------|----------------------|-----------|
| 14 | **Agent commits; Done has a safety net.** The brief instructs the agent to commit its work; the app never commits behind your back. The Done flow detects a dirty worktree, shows the diff stat, and offers one-click "commit remaining changes" before push/PR. | Auto-checkpoint commits on every Stop (history noise, commits half-done states); no policy (PR step just fails) | Honest history, no surprise commits, and the failure mode (agent forgot to commit) is caught at the exact moment it matters. |
| 16 | **Retention: clean on PR merge + TTL; nothing is ever destroyed by automation.** Worktrees survive Done. On PR merge (watched via `gh`) — or a configurable TTL for PR-less tickets — the app prompts to archive + clean. Archived tickets leave the board into a per-project, searchable **Archive** that permanently retains the event log, transcripts, branch name, and PR link; deleting from the Archive is the only destructive act, always explicit. | Clean immediately on Done (kills resume exactly when review bounces); manual-only (disk chore) | Reopen-and-resume stays cheap while review is live; the audit trail (goal 2) is sacred. |
| 17 | **Scratch sessions: per-project Sessions surface + promote.** One keystroke opens a ticket-less session (main checkout, no worktree, no board involvement) — still recorded in the same session history. "Promote to ticket" creates a ticket, links the transcript, and optionally moves work into a worktree/branch. | Auto-creating placeholder tickets (litters the board); deferring to v2 (recreates the original disconnect, loses transcripts) | Zero friction to start exploring, no audit hole, clean path from poking-around to tracked work. |
| 19 | **Attachments: materialize files + list paths.** On launch, attachments are copied into a gitignored ticket-scoped dir in the worktree (`.volli/attachments/`); the brief lists each path with its label and instructs the agent to read them; URLs pass through as URLs. | Per-harness native embedding (divergent adapters for marginal gain); URLs/text only (screenshots are the most common spec artifact) | One mechanism, full fidelity, identical across every harness that can read files. |
| 20 | *(“primary session” → the ticket's live sessions, per #39)* **Backward moves interrupt, never kill.** Dragging a ticket out of the active columns sends the primary session an interrupt (Esc-equivalent — stop the current turn); terminals stay alive. If a terminal was closed by the user, a session-resume interface brings it back. Underlying asymmetry (made explicit with #78's implementation): automation only ever de-escalates; escalation — starting or resuming an agent, i.e. spending tokens — is always a human act, and every automated interrupt is announced (toast + event), never silent. Derived rule: **hook events arriving on the heels of a manual move are stale — the manual move wins** (else the interrupt's own Stop hook would bounce the ticket right back). | Killing the PTY (destroys live context); blocking the move (fights the human); label-only moves (Todo with running agents — the exact lie this app exists to kill) | Board stays truthful; nothing is lost. |
| 21 | **Re-entering Doing resumes by default.** Live terminal → untouched, keep talking. Dead terminal with a resume command → relaunch it (`claude --resume`). Only a ticket with no prior session gets the fresh composed prompt; "Start fresh session" is always in the ticket menu. | Always-fresh (agent amnesia exactly when "address the review feedback" needs context); ask-every-time (modal for a 90%-obvious answer) | The most common bounce (Needs Review → Doing) keeps the agent's context. |

| # | Decision | Alternatives rejected | Rationale |
|---|----------|----------------------|-----------|
| 38 | **Worktrees materialize at session boot; column moves have zero side effects.** The first session created in a worktree-enabled ticket runs an idempotent, single-flight `ensure` (worktree + branch → copy step → setup) before its PTY spawns; later sessions find it ready. Board moves are pure data mutations. Column-entry effects (Doing warm-up, auto-launch, symmetric lifecycle moves) are deferred to a future **user-configurable column-automations system** with its own settings surface. On ensure failure the move stands, the error is toasted + logged, and the session does **not** fall back to the main checkout — the worktree toggle is the only sanctioned path there. | Column-driven creation (the original board-semantics table); eager warm-up on Doing entry; silent main-checkout fallback | Nothing spawns on the user's disk until execution genuinely begins; one seam covers every session path (composer kickoff, `+` button, CLI); a fallback to the shared checkout reintroduces the exact clobbering disease worktrees cure. |
| 39 | **Primary sessions are deleted as a concept.** All ticket sessions are equal weight (as ticket-detail-mvp shipped); setup runs in whichever session triggered worktree creation — definitionally the first. The future automations system defines its own trigger vocabulary instead of resurrecting a blessed session. | Reintroducing a primary marker in the tab strip; ordering conventions ("first tab is special") | Cognitive overload with no real value; automation semantics belong to the automations design, not to a per-ticket flag users must manage. |
| 40 | **Worktree home: `~/.volli/worktrees/<project-dirname>-<short-id>/<DISPLAY-ID>-<slug>/`; raw git CLI only.** App-owned and outside both the repo and `userData` (space-free, human-legible paths that rhyme with the branch name; watchers in the main checkout never recurse into worktrees; cleanup never touches user folders). Execution is `execFileSync git …` behind the injectable `RunGit` seam — never libgit2/native bindings. Creation runs a proactive collision matrix (branch checked out elsewhere → friendly hard fail; stale metadata → `git worktree prune` + one retry; dir-exists / dir-missing reconciliation) on `realpath`-canonicalized paths. Base resolution is deterministic and offline: ticket `baseBranch` → project `base_branch` → detection, from local refs (remote-tracking fallback), stamped onto the ticket at creation; **no implicit fetch, ever**; an existing ticket branch is reused, never reset. | `userData` (space in "Application Support" breaks unquoted scripts); nesting under `<repo>/.volli/` (watcher recursion, cleanup inside user repos); libgit2 (clobbers uncommitted files git CLI refuses to; corruption reports); T3-style fetch-first (network hang on ticket start) | Every serious tool (T3, Vibe Kanban, Sculptor, Conductor, Claude Code) keeps worktrees app-owned; Vibe Kanban's libgit2 rationale is decisive; local-first means kickoff never waits on the network. |
| 41 | **Worktree prep: `.worktreeinclude` + built-in defaults; sentinel-gated setup in the live terminal; cwd = worktree.** Copy rules live in a repo-root `.worktreeinclude` (gitignore syntax — the de-facto standard Conductor and Claude Code independently converged on; one file drives all three tools) layered over built-in defaults (`.env*`, harness local settings such as `.claude/settings.local.json`), `!` negation wins, traversal-guarded, never overwriting. The setup command stays a per-project DB setting. Setup is typed into the session's terminal wrapped with an exit-code sentinel; the harness command is written **only on exit 0** — visible, interactive, tracked, and pane-safe at once. The PTY's cwd *is* the worktree; the composed brief opens with an explicit orientation preamble (worktree path, branch, base; main checkout is reference-only) so agents never "reorient" themselves out of it. | App-configured copy-globs (original #15 — a Volli-only setting restating a standard); `setup && agent` one-liner (outcome invisible to the app); hidden setup process (violates #15 visibility); running setup as the pane's primary process (cmux #5032: pane dies with it); main-checkout cwd + per-harness "work over there" flags (no universal flag; agent's default edits land in the shared checkout) | Modern harnesses natively resolve linked worktrees for trust/settings via the shared `.git`, and the copy defaults close the gitignored-local-config gap — the one real loss cwd-in-worktree ever had. |
| 42 | **Persist identity, compute state; one module owns worktrees.** Durable truth is only `worktree_path`/`branch`/`base_branch` (+ the event log: `worktree_changed`, and a new `worktree_failed` with stage + stderr). Runtime phase (`creating → copying → setting-up → ready \| failed`) is transient, main-process-owned, IPC-broadcast, and recomputed from disk on boot — never trusted from a row. All worktree git execution, the ensure pipeline, phase registry, and event emission live in one `src/main/worktree/` module behind a narrow interface (`ensure`/`remove`/`getState`); `getState` returns the single composed answer so no one joins DB + events + stores to learn what happened. | A persisted status enum (lies after every crash); scattering git calls across pty/ipc/commands | A status column *will* diverge from disk; single-module ownership is the maintainability floor. |
| 43 | **Startup orphan sweep: three tiers, conservative by construction.** (1) `git worktree prune` — always safe. (2) Clean orphans (no DB row, empty status, no unreachable commits) are auto-removed, branch retained — a clean worktree dir is cache, not data, so #16's no-destruction law is honored. (3) Dirty orphans are never auto-removed: surfaced once via toast and listed in Settings → Worktrees with explicit Reveal/Delete. Dirty detection errs toward dirty: untracked files, sequencer state (merge/rebase/cherry-pick/bisect), unreachable commits, `git worktree lock`, submodule drift, **or any git failure/ambiguity** all count, and removal re-verifies cleanliness immediately before deleting. TTL-based periodic sweeps stay with the retention work (#16) and will reuse these tiers. | Vibe Kanban's force-remove-unmatched (their dirs are OS-temp; ours are durable); manual-only cleanup (T3's disk chore) | Automation may delete only what git provably already holds; everything else waits for a human. |

## The core loop

### Board semantics

| Column | Meaning | Automated behavior |
|--------|---------|--------------------|
| **Backlog** | Captured, not committed | none |
| **Todo** | Committed, ready to run | none |
| **Doing** | Agent (or human) actively working | Column entry itself has no side effects (#38). The ticket's **first session boot** materializes the worktree: branch `volli/<ID>-<slug>` (unless opted out) → copy `.worktreeinclude` files → run the project setup command visibly in that terminal, sentinel-gated → materialize attachments → compose prompt → write the harness command. Column-entry automation (warm-up, auto-launch) and re-entry resume (#21) arrive with the configurable automations system. |
| **Needs Review** | Blocked on a human — always | **⚠️ Not built — this row describes intent, not behavior.** Nothing enters this column automatically today: no harness hook configs are generated, `volli session done` records an event that moves no ticket, and no notification fires for an agent needing you. Reaching this column is a manual drag. Building it is the open #8 sketch. |
| **Done** | Work accepted | Entry has no side effects. Per #44/#45 the Details rail carries **one adaptive split button** (Commit & create draft PR / Push & create draft PR / Push updates / View PR) plus a merge-base context line — a button, never a gate. Worktree survives Done; on PR merge or Done-TTL, prompt to archive + clean (#16). |

Moves are bidirectional and manual moves always allowed; automation never fights the human. Moving a ticket backward out of the active columns *interrupts* the ticket's live sessions (Esc-equivalent) without killing terminals; hook events that arrive on the heels of a manual move are treated as stale — the manual move wins. The asymmetry is the principle: **automation only ever de-escalates** (interrupt, park, archive-on-TTL) — starting or resuming an agent spends tokens and is always a human act — **and never silently**: an automated interrupt announces itself where the mover is looking (toast naming the ticket, jump-to-ticket action) on top of its `sessions_interrupted` event.

**Archive:** a per-project view, not a sixth column. Lifecycle automation never destroys data — archiving removes the worktree but permanently retains the ticket, event log, transcripts, branch name, and PR link. Deleting from the Archive is the only destructive act, always explicit.

### Ticket anatomy

- Identity: per-project prefix + number (e.g. `VC-12`), Linear-style.
- Content: title, rich description (markdown), attachments (files, URLs), labels, priority.
- Execution config: harness (Claude Code / Codex / Opencode / custom command template), worktree toggle, base branch.
- Live state: worktree path, branch, session statuses.
- History: every status change, session start/stop, and comment in an append-only event log; full transcripts linked.

### Prompt composition

When a ticket enters Doing, the adapter renders the harness command from a template, e.g.:

```
claude "$(volli ticket brief VC-12)"
```

where `volli ticket brief` emits the ticket's title, Ticket Body, attachment paths/URLs, and one paragraph teaching the agent the `volli` CLI (the resolved-reference manifest is the unbuilt #62 sketch) (how to move the ticket, comment, ask for review). Custom harnesses get `{{brief}}`/`{{ticket_id}}` template variables. The generated Brief is the harness-independent contract; future acceptance tests should prove that each first-class harness actually receives it, can discover the CLI, and can read its referenced context.

### The `volli` CLI

The local CLI exposes the planning surface described in decisions #34–37. Run `volli help` for the command contract; keep this document focused on product semantics rather than duplicating executable help.

`volli help` is the primary discovery surface and the CLI's authoritative reference — a blind agent should never need the skill pack to operate it (measured: thin help forced ~108 commands and ~62k tokens across 7 basic tasks). It is generated from the parser's own `CommandSpec`/`OptionEntry` tables (the same way `volli help exit-codes` renders from `AGENT_ERROR_CODES`), so reference and reality cannot drift: `volli help` prints a grouped compact reference, `volli help <command>` a full detail view, and every vocabulary rejection enumerates the valid tokens inline. The skill pack is therefore activation + norms only — it points at `volli help` and never restates flag syntax. Token budgets are tested contracts, not aspirations: the bare reference and each command's detail have char/token ceilings asserted in unit tests and an e2e token bench (`apps/desktop/e2e/agent-cli-token-bench.mjs`).

Harness adapters generate hook configs on session launch — e.g. Claude Code `Stop` → `volli session done`, `Notification` → `volli notify` — scoped to the worktree so the user's global hook config is untouched.

### Sessions & audit history

- Each session records: harness, command, cwd, start/end, resume command, transcript file.
- Ticket view shows the live terminal; project view shows a searchable session history ("what has been done here, by whom, when, and why").
- On app relaunch: layout restored, each interrupted session offers one-click resume.
- **Scratch sessions**: each project has a Sessions surface beside the board — one keystroke opens a ticket-less session (main checkout, no worktree, no board involvement), recorded in the same history. "Promote to ticket" links the transcript to a new ticket and optionally moves the work into a worktree/branch.

## Open questions

The original parked questions (worktree hygiene, multi-agent tickets, exploratory sessions, attachment fidelity, retention) were all resolved July 2026 — see decisions 13–21 in the log above. Remaining minor items, with defaults chosen (revisit only if they hurt):

- **Base-branch drift**: no auto-rebase in v1; the card shows a "behind base by N commits" indicator and the human tells the agent to rebase when it matters.
- **Hook-config merging** *(feeds #8)*: adapters write hooks into worktree-scoped harness settings by *merging* into any copied project settings, never clobbering them. No such writer exists yet — it is the first thing the automations branch needs.
- **Return-to-Doing signal on custom harnesses** *(feeds #8)*: adapters use native hooks where available (e.g. Claude Code `UserPromptSubmit`); the fallback heuristic is Enter-terminated input written to an agent session's PTY.
