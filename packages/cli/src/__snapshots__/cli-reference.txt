============================================================================
volli help
============================================================================
volli — self-documenting planning CLI for coding agents.

Read
  identify [--project <p>]
  board [--project <p>]
  ticket list [--status <column>] [--priority low|medium|high] [--label <name>] [--project <p>] [--limit <n>]
  ticket show <id> [--events <n>] [--comments <n>]
  ticket events <id> [--limit <n>]
  ticket brief <id>
  worktree status [<id>]
  worktree diff [<id>] [--working-tree]
  project list
  label list [--project <p>]
  model list [--all]

Write
  ticket create --title <text> [--body <text>|--body-file <path>] [--priority low|medium|high] [--status <column>] [--label <name>]... [--project <p>] [--harness <h>] [--base <branch>] [--no-worktree]
  ticket update <id> [--title <text>] [--body <text>|--body-file <path>|--append <text>|--edit <old> <new>] [--priority low|medium|high] [--add-label <name>]... [--remove-label <name>]... [--harness <h>] [--base <branch>]
  ticket move <id> --to <column>
  ticket comment <id> [-m <text>|--file <path>]
  ticket archive <id>

Session
  session start <id> [-m <text>] [--title <text>] [--model <provider/model>] [--reasoning <level>]
  session list [--project <p>] [--ticket <id>]
  session peek <id> [--lines <n>]
  session done [--reason <text>]
  session blocked [--reason <text>]
  session link <id>
  notify -m <text> [--title <text>]

App
  app launch [--timeout <n>]
  prompt baseline [--ticket <id>] [--project <p>]
  doctor [--fix]
  help [<command> | <topic>]

Context: --project flag, then VOLLI_SESSION/VOLLI_TICKET, then a registered cwd.
Add --json to any command for structured output.
Ids: display ticket ids (VC-12); short session ids from session list.
volli help <command> for detail. Topics: exit-codes, addressing, json, orchestration.

volli help identify
============================================================================
identify — Resolve and print the active project, ticket, session, and session environment.

Usage: volli identify [options]

Options:
  --project <p>  Resolve against this project instead of the context ladder.

Example: volli identify

Notes:
- The env block reports the session PATH, how it was adopted, where each measured tool (git, gh, node, npm, pnpm, yarn, bun) resolves, and whether workspace dependencies are installed — read it before probing for tools.
- env.requiredTools names what THIS project implies: git for a repository, node and the lockfile's package manager for a JS workspace. A `-` tool not listed there is one nothing here runs, not a fault.
- env.provenance is the boot adoption; env.interactiveProvenance is the later pass that picks up what your shell's interactive startup files export (nvm, bun, rbenv, pyenv, mise). `pending` there means that pass has not landed yet.

volli help ticket create
============================================================================
ticket create — Create a ticket (defaults to Backlog).

Usage: volli ticket create --title <text> [options]

Options:
  --title <text>              Ticket title.
  --body <text>               Body text.
  --body-file <path>          Body from a file.
  --priority low|medium|high  Priority.
  --status <column>           Initial column. (valid: backlog, todo, doing, needs-review|review, done)
  --label <name>              Add label (repeatable).
  --project <p>               Project (name/prefix/path).
  --harness <h>               Harness id. (valid: claude-code, codex, cursor, opencode, or a registered, trusted harness)
  --base <branch>             Base branch.
  --no-worktree               Skip worktree isolation.

Example: volli ticket create --title "Fix auth" --label bug

Notes:
- Defaults to Backlog unless --status is set.
- --body and --body-file are mutually exclusive.

volli help ticket update
============================================================================
ticket update — Update a ticket's fields or body.

Usage: volli ticket update <id> [options]

Options:
  --title <text>              Replace the title.
  --body <text>               Replace the body.
  --body-file <path>          Replace body from a file.
  --append <text>             Append to the body.
  --edit <old> <new>          Replace one <old> with <new>.
  --priority low|medium|high  Set priority.
  --add-label <name>          Add label (repeatable).
  --remove-label <name>       Remove label (repeatable).
  --harness <h>               Set the harness. (valid: claude-code, codex, cursor, opencode, or a registered, trusted harness)
  --base <branch>             Set the base branch.

Example: volli ticket update VC-12 --edit "old" "new"

Notes:
- At most one body mutation per call.
- --edit needs exactly one match for <old>.

volli help session start
============================================================================
session start — Start an agent chat session on a ticket.

Usage: volli session start <id> [options]

Options:
  -m <text>                 Kickoff message.
  --title <text>            Explicit session title.
  --model <provider/model>  Model override.
  --reasoning <level>       Reasoning level override. (valid: off, minimal, low, medium, high, xhigh, max)

Example: volli session start VC-12 -m "Fix the flaky auth test"

Notes:
- Runs in the app: attended-only, never headless; the board does not move.
- Submits a kickoff turn; -m replaces the default kickoff text and names the session.
- --title sets a permanent title; --model/--reasoning override the app default.

volli help session peek
============================================================================
session peek — Peek at what a session is doing: terminal output, or a chat's tail.

Usage: volli session peek <id> [options]

Options:
  --lines <n>  How much trailing output to show.

Example: volli session peek a1b2c3 --lines 60

Notes:
- Handle is a short session id from session list — terminal or chat.
- A chat answers activity, last-event age, turn depth, then its transcript tail.
- --lines is trailing terminal lines (60), or chat messages (12).
- Keep peeks narrow — output consumes the caller's context.

session done — Record that this session's work is finished.

Usage: volli session done [options]

Options:
  --reason <text>  Human-readable reason.

Example: volli session done --reason "Tests pass"

Notes:
- Acts on VOLLI_SESSION; needs a Volli session.
- Records the signal in the session ledger; the board does not move. Use ticket move for that.

volli help prompt baseline
============================================================================
prompt baseline — Measure the prompt baseline a fresh chat Session starts with, per section.

Usage: volli prompt baseline [options]

Options:
  --ticket <id>  Price a Ticket Session for this ticket instead of a project chat.
  --project <p>  Resolve against this project instead of the context ladder.

Example: volli prompt baseline

Notes:
- Token counts are estimates at 4 characters/token; the provider's own meter is the count of record.
- Each section names a cache class — how often its bytes are bought again, claimed rather than measured; message-side sections are marked, and never invalidate the Cache Prefix.
- Excludes tool definitions, the user's first message, and provider overhead, which ride on top of everything counted here.
- --ticket prices a Ticket Session instead, including that ticket's Brief.

volli help doctor
============================================================================
doctor — Audit the harness integration and report what it is actually doing.

Usage: volli doctor [options]

Options:
  --fix  Regenerate, re-run Session PATH adoption, then re-check.

Example: volli doctor --fix

Notes:
- Reports outcomes, not configuration: whether typing a harness's name here really reaches Volli's wrapper.
- Run it inside a Volli terminal — several checks describe the shell it runs in.
- --fix regenerates the wrappers, harness configs and shell integration, then re-runs both Session PATH adoption passes. It names the outcome and added directories for new Sessions; a Session already running keeps its startup environment.
