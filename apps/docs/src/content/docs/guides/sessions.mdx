Start a chat for your project, or for one ticket. A chat becomes a **Session**
when you send its first message. Volli saves the Session, so you can leave and
come back without starting a duplicate.

## Start a chat

Before you start a chat, set a default model in **Settings → Models**.

- In **Home**, select **Chat** to start a Board chat. It works in the project's
  main checkout and has no ticket of its own.
- In a ticket workspace, select **Chat** in **Sessions** to start a ticket
  chat. It uses that ticket's selected destination: a **New worktree** or the
  project's **Project checkout**.

You can also choose **Chat** from the menu beside the **Chat** control. The
composer opens as a **Chat Draft**, which has no history yet. Write the opening
message and send it to create the Session. Opening a draft creates no Session
and no worktree, and closing an empty draft leaves nothing behind. Your draft
text and staged files stay when you navigate or reopen the app.

<Aside type="note">
  Moving a ticket to **Doing** updates its status. It starts a Run only when an
  enabled Automation is armed for that column. You can start a chat without an
  Automation.
</Aside>

## Send messages while the agent works

While the agent works on a reply, **Queue** adds a message for later. Select
**Steer** on a queued message, or press `⌘Enter` in the composer, to send an
instruction into the current turn without interrupting it. **Remove** drops a
queued message.

Select **Stop turn** to interrupt the current response. This does not undo file
edits or commands that already ran, so check the result before sending the
next instruction.

## Inspect Session activity

The **Activity Island** appears above the composer when the Session has
activity to show:

- **Browser Tabs**: inspect pages the agent opened.
- **Subagents**: peek at a Session the agent delegated work to, open it, or
  stop it. These children share the parent's working directory and have no row
  in the Session list.
- **Plan**: read the agent's checklist and its completed-item count.
- **Background shells**: inspect output from a dev server or another
  long-running command. These stop when the Session's connection ends; they do
  not survive a relaunch.

## Return to a Session

In **Home**, select an existing chat under **Board sessions** in the rail. For
a ticket chat, open the ticket workspace and select the Session under **Now →
Sessions**. Its transcript stays with that Session when you switch tabs,
navigate away, or close its live connection. Sending another message to a
disconnected chat reconnects that Session instead of creating a second
conversation.

Closing a chat tab does not delete the Session. Starting a new chat creates a
different Session.

## Peek at a Session without opening it

Hover over a Session in the sidebar's **Active** or **Previous** list, or under
a ticket's **Now → Sessions**. After a moment, a card shows the Session's
state, what it did most recently, and any question it is waiting on. Hover over
a ticket's folder instead to see that ticket's Sessions.

- Select **Answer** on a waiting question, or **Send** to message a Session,
  to reply from the card. `⌘.` does the same for the card on screen. The reply
  goes to that Session; you stay where you were.
- Select **Open session** to go to the full conversation.
- Press `Esc` to step back: out of the reply field, then the card.

From the keyboard, focus a row and press `Space` to peek, and `Space` again to
reply. `↑` and `↓` (or `K` and `J`) move between rows. A peek does not mark a
Session as read; press `U` on a focused row to toggle its unread dot.

## Choose a terminal companion

Choose **Terminal** from the menu beside **Chat** when you need a shell, or want
to run a terminal app (a TUI) yourself. A terminal is a separate manual
workflow, not a fallback when a chat cannot start. See
[Terminal companions](/guides/terminal-companions/) for what it can do and what
it keeps.

## Start work from an Automation

An Automation Run starts a new Session whose first message is the Automation's
saved **Instructions**. A ticket-triggered Run uses the ticket; a scheduled Run
starts a Board Session in the project's main checkout. See
[Automations](/guides/automations/) for how to run one and inspect Run history.

If a chat stops or loses provider access, see
[Recover a Session](/guides/recover-session/). See
[Chats and worktrees](/guides/agents-and-worktrees/) for the checkout each chat
uses.
