Use **Configure → MCP Servers** to connect a project to Model Context Protocol
(MCP) tools. You can add a local process or a remote Streamable HTTP endpoint,
test the connection, and choose tools explicitly.

## Add a server

Have the server’s executable and arguments, or its Streamable HTTP endpoint,
ready. **Test and discover** starts a local command as your macOS user, or
connects to the remote endpoint. Review the command or endpoint before testing.

1. In the project, open **Configure → MCP Servers** and select **Add server**.
2. Enter a **Name**, then choose a **Transport**.
3. For **Standard input/output**, enter the **Executable** and **Arguments (one per line)**. For **Streamable HTTP**, enter the **Endpoint URL**.
4. Select **Test and discover**. When the catalog loads, select only the tools you want to offer. Newly discovered tools are not selected for you.
5. Select **Save server**. Testing alone does not save the configuration.

To change an existing server, select **Edit** in its row. You can change its
configuration, enable or disable the server, and choose which discovered tools
to enable. Use **Refresh** to read its tool catalog again.

## Choose tools for Sessions

The server’s **On** checkbox and each tool checkbox control what new root Sessions
for this project can use. Existing Sessions keep every tool they already hold
and can gain additions. Tools routed only through Code Mode become available
before the next program, with a short appended announcement. Other additions
wait for a cold prompt cache, compaction or a model switch. Each update appears
as an expandable “Tools updated” transcript row.

Delegated helpers inherit their parent's current recorded MCP tools, including
refreshed additions, not the project's later selection. Running helpers gain
additions by the same rules, bounded by their parent.

When [Code Mode](/guides/code-mode/) is on, a server with more than 20 enabled
tools, or with very long tool definitions, is not sent to the model tool by
tool. A Session sees the server's name and tool count and finds the tools it
needs from a short program, which keeps every request smaller. Enabling only
the tools you need keeps a server under that size.

Prefer switching a server off when you want new root Sessions to stop receiving
its tools. This keeps the configuration older Sessions need and does not revoke
their existing tools or those inherited by their delegated helpers.

Removing a server leaves its existing tool names on updated Sessions; calls
return a named unavailable error. Re-adding the server under its original ID
restores the connection. On older app builds, the missing configuration may
prevent reattachment until it is restored under that ID.

## Review the trust boundary

A local MCP command runs as you. A remote server receives the arguments sent to
its tools. Treat server metadata and tool results as untrusted data, not as
instructions. Review the discovered tool names and descriptions before enabling
them.

Volli supports standard input/output and Streamable HTTP, not legacy SSE-only
endpoints. It does not support authenticated HTTP endpoints, custom headers, or
secret environment fields. Use a server that needs none of those options. Do
not put credentials in the endpoint URL.
