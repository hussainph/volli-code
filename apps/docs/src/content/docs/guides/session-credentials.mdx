When an agent needs an API key or another credential for a command, ask it to
request the credential through Volli. Enter the value in the **Credential
requested** card, not in a chat message.

The agent requests an environment variable name, such as `API_TOKEN`. Volli
supplies the value to its shell commands. The tool's reply tells the agent
whether you supplied or declined it; it does not return the value.

## Answer a credential request

1. Check the **Session** and **Project** named in the **Credential requested**
   card. **The agent says** contains the agent's explanation of what it needs.
2. Enter the credential in the password field named for the environment variable.
3. Choose a **Scope**:

   | Scope | Use |
   | --- | --- |
   | **Session** | Keep it in memory for this Session's current connection |
   | **Project** | Save it for Sessions in this project |
   | **Always** | Save it for Sessions across projects on this Mac |

4. Select **Submit credential**, or **Decline** if you do not want to provide it.

**Session** is the default. Its value is cleared when the Session's connection
ends and does not survive restarting Volli. **Project** and **Always** values
are stored encrypted locally. If the same name exists in several scopes,
**Session** takes precedence over **Project**, then **Always**.

Shell commands can use the credential and send it to another service. Volli
tries to redact exact values from tool output, but encoded or transformed
values can leak. Review commands that handle credentials and use keys with only
the access the task needs.

## Replace or revoke a saved credential

Open the project's **Configure → Secrets** page in Settings. The list shows
names, scopes, and last-used times; it does not reveal stored values.

- Choose **Replace** from a credential's actions menu to enter a new value.
- Choose **Revoke…**, then **Revoke**, to stop supplying it to later commands.
- Use **Refresh** to read the list again.

Revoking a credential in Volli does not revoke it at its provider or remove it
from a process that already received it. Revoke the key with that service too
if it may have been exposed.

## If saved secrets are locked

In **Configure → Secrets**, select **Try again** after resolving the reported
credential-store problem. **Reset…**, when offered, sets aside saved
**Project** and **Always** credentials; you will need to enter them again.

See [Local data and network access](/reference/data-and-privacy/) for the
boundaries of local tools and outbound requests.
