An **Automation** is a saved, named way to start work. It stores reusable
**Instructions**, one **Trigger**, and a **Runtime**. Every Run opens a fresh
Session; it does not resume an existing Session.

## What an Automation saves

| Part | What it controls |
| --- | --- |
| **Name** | How you identify it in the Automations page and run menus. |
| **Instructions** | The first message sent to the new Session. They support the chat composer's `/` template and Skill references and `@` file references. |
| **Trigger** | What starts it besides you: **Only when I run it**, **Ticket enters**, or **On a schedule**. |
| **Runtime** | The model selection for the Run, inherited from project defaults or pinned to a tier or model. |

A Run records which Automation it used and the model and reasoning that started
the Session. Its history links back to that Session.

## Choose a Trigger

A Trigger says what can start an Automation automatically. You can always run a
saved Automation by hand, whatever its Trigger.

### Only when I run it

This Trigger adds no automatic start. Use [Create a manual Automation](/guides/automations/create/)
to save one you will start yourself.

### Ticket enters

This Trigger offers the Automation in its selected board columns. A column can
arm one of the Automations it offers. See [Arm a column Automation](/guides/automations/columns/).

### On a schedule

This Trigger starts a project-level Board Session at its saved cadence. See
[Schedule an Automation](/guides/automations/schedules/) for time zones and
missed occurrences.

## Automatic trigger settings

Turn on **Automatic triggers** on this Mac to let an Automation start from its
Trigger. The switch is off by default and does not travel with the project. A
column Trigger also needs an armed column. A manual Run still works while the
switch is off.
