An **Automation** is a saved, named way to start work. It stores reusable
**Instructions**, one **Trigger**, and a **Runtime**. Every Run opens a fresh
Session; it does not resume an existing Session.

## What an Automation saves

| Part | What it controls |
| --- | --- |
| **Name** | How you pick it out on the Automations page and in run menus. |
| **Instructions** | The first message the new Session receives. They support the chat composer's `/` references to Commands and Skills, and `@` file references. |
| **Trigger** | What starts it besides you: **Only when I run it**, **Ticket enters**, or **On a schedule**. |
| **Runtime** | The model choice for the Run, inherited from project defaults or pinned to a tier or model. |

Each Run records which Automation it used and the model and reasoning that
started the Session. Its history links back to that Session.

## Choose a Trigger

A Trigger says what can start an Automation automatically. You can always run a
saved Automation by hand, whatever its Trigger.

### Only when I run it

This Trigger adds no automatic start. To save an Automation you start yourself,
see [Create a manual Automation](/guides/automations/create/).

### Ticket enters

This Trigger offers the Automation in the board columns you select. A column can
arm one of the Automations it offers. See [Arm a column Automation](/guides/automations/columns/).

### On a schedule

This Trigger starts a project-level Board Session at the saved cadence. See
[Schedule an Automation](/guides/automations/schedules/) for time zones and
missed occurrences.

## Automatic trigger settings

Turn on **Automatic triggers** to let an Automation start from its Trigger. The
switch is off by default and stays on this Mac, so it does not travel with the
project. A column Trigger also needs an armed column. You can still run an
Automation by hand while the switch is off.
