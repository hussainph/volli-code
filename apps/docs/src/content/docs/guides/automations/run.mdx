A **Run** is one invocation of a saved Automation. Each Run opens a fresh
Session with the Automation's **Instructions** as its first message. It does
not resume an existing Session.

## Run an Automation by hand

From the **Automations** page, select an Automation and choose **Run**. For an
Automation without an **On a schedule** Trigger, choose a ticket in the picker.
A scheduled Automation runs at the project level and opens a Board Session.

You can also start a Run from a ticket's **Automations** section or its board
card's **Automations** context-menu item. In the ticket workspace, choose a
model under **Run on** for a one-time model and reasoning override; the
Automation armed for the ticket's column appears first. Use the command palette
to run an Automation when it is listed there.

The **Automatic triggers** switch controls only automatic starts. You can run
an Automation by hand while its switch is off. A Run uses the Automation's
**Runtime** unless you select a one-time override from the ticket workspace.

## Read Runs and skipped occurrences

Select an Automation to see its **Runs** list. Rows are newest first and show
the Automation name, target, resolved model and reasoning, how the Run started,
and when. Select a Run to open the Session it created. The row records the
model that actually started that Session, even if the Automation's Runtime
changes later.

A missed scheduled time appears in history with its reason. Select **Run now**
to start one Run at the same project scope. It does not replay every missed
occurrence. See [Schedule an Automation](/guides/automations/schedules/) for how
Volli handles missed schedule times.

Select **Project activity** in the Automations page to read the combined Runs
and skipped occurrences across the project. This history remains available if
you later delete an Automation; deleting its record does not delete past Runs.
