Use **Settings → Models** to connect provider accounts, choose default models,
control which models appear in pickers, and set automatic compaction. When
Volli creates a Session, it records the model for that Session; changing a
default does not change the model already recorded for an existing Session.

## Connect a provider

1. In **Settings → Models → Available to connect**, find your provider.
2. Select **Sign in** and follow that provider's prompts. The available method
   may use a browser, a device code, or an API key.
3. In **Default models → Board chats**, choose an available model.
4. Optional: Set a different **Ticket Sessions** model for task work.

A provider appears under **Signed in** once its credentials are saved. If a
request later reports an authentication failure, repair the connection there
and follow [Recover a Session](/guides/recover-session/).

## Choose a default model

New chats use the composer's model choice first, then the project's override,
then the matching app-wide default. To set the project override, open
**Configure → Sessions → Chat → Model** and choose a model and reasoning level.
This applies to new Board and Ticket chats in that project. An Automation's
**Project default** also uses this override.

In **Settings → Models**, the **Default models** section has six app-wide rows.
Each row stores a model and its reasoning level when you choose one. The table
shows the fallback when no project override or explicit model choice applies.
Selecting a named tier uses that tier's app-wide row instead of the project
override.

| Row | Used for | When unset |
| --- | --- | --- |
| **Board chats** | Board Sessions | Choose a model here; this is the root default. |
| **Ticket Sessions** | Ticket Sessions | Uses **Board chats**. |
| **Fast** | Quick, low-cost work | Uses **Ticket Sessions**. |
| **Deep** | Complex reasoning, planning, and review | Uses **Ticket Sessions**. |
| **Visual** | Work with images, screenshots, and pages | Uses **Ticket Sessions** only if that model accepts images. Otherwise, choose a Visual model. |
| **Utility** | Chat names and summaries | Uses the chat’s own model. |

Choose **Settings → Models**, then select a model in the row for the kind of
work you want to configure. If you choose a model explicitly, select one of its
available reasoning levels in the adjacent control. The Visual row only offers
models that accept image input.

## Provider accounts and model pickers

In **Signed in**, manage providers you have connected. **Available to connect**
lists other providers. A provider’s models appear in default-model selectors
when they are available to your account. Use **Catalog** to hide or show
individual models in pickers; hiding a model does not remove the provider
account.

## Automatic compaction

**Automatic compaction** is on by default. It lets a Session shorten its
working context when it reaches the runtime’s threshold. Turn it off if you do
not want threshold-triggered compaction. The setting does not disable `/compact`
or recovery after a provider rejects a turn because the context is too large.

## Usage readings

Volli shows two different kinds of usage:

- **Session usage** summarizes model operations recorded for a Session. Its cost
  can be provider-reported, estimated from Volli’s model catalog, partly priced,
  or unavailable. Treat a catalog estimate as an estimate, not as an invoice.
- **Usage limits** shows subscription usage windows reported by supported
  providers. Open the **Usage limits** control beside `⌘K` to check them; they
  are not in **Settings → Models**.

See [Settings and configuration](/guides/settings/#configure) for project
configuration and the other Settings
surfaces, and [Chats and worktrees](/guides/agents-and-worktrees/) for the
Board and Ticket Session workflows.
