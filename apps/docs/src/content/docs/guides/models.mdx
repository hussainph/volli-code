Use **Settings → Models** to connect provider accounts, choose default models,
control which models appear in pickers, and set automatic compaction. When
Volli creates a Session, it records the model for that Session. Changing a
default does not change the model already recorded for an existing Session.

## Connect a provider

1. In **Settings → Models → Available to connect**, find your provider.
2. Select **Sign in** and follow the provider's prompts. Depending on the
   provider, you may sign in with a browser, a device code, or an API key.
3. In **Default models → Board chats**, choose an available model.
4. Optional: Set a different **Ticket Sessions** model for ticket work.

A provider appears under **Signed in** once its credentials are saved. If a
request later fails to authenticate, repair the connection there and follow
[Recover a Session](/guides/recover-session/).

## Choose a default model

New chats choose a model in this order: the composer's model choice, then the
project's override, then the matching app-wide default. To set the project
override, open **Configure → Sessions → Chat → Model** and choose a model and
reasoning level. The override applies to new Board and Ticket chats in that
project. An Automation's **Project default** uses the same override.

**Default models** in **Settings → Models** has six app-wide rows. Each row
stores a model and its reasoning level when you choose one. The table shows
what applies when no project override or explicit model choice is set. When you
pick a named tier, that tier's app-wide row applies instead of the project
override.

| Row | Used for | When unset |
| --- | --- | --- |
| **Board chats** | Board Sessions | Choose a model here; this is the root default. |
| **Ticket Sessions** | Ticket Sessions | Uses **Board chats**. |
| **Fast** | Quick, low-cost work | Uses **Ticket Sessions**. |
| **Deep** | Complex reasoning, planning, and review | Uses **Ticket Sessions**. |
| **Visual** | Work with images, screenshots, and pages | Uses **Ticket Sessions** only if that model accepts images. Otherwise, choose a Visual model. |
| **Utility** | Chat names and summaries | Uses the chat’s own model. |

Choose **Settings → Models**, then select a model in the row for the kind of
work you want to configure. If you choose a model explicitly, select one of its
available reasoning levels in the control beside it. The **Visual** row offers
only models that accept image input.

## Provider accounts and model pickers

In **Signed in**, manage the providers you have connected. **Available to
connect** lists other providers. A provider's models appear in default-model
selectors when your account can use them. Use **Catalog** to hide or show
individual models in pickers. Hiding a model does not remove the provider
account.

## Decision model

A decision model is a second, much smaller kind of model. It does not write
text. It reads some structured data and answers typed questions about it:
pick one of several options, place it on a scale, or answer yes or no. Each
answer comes with probabilities and a confidence. Because it writes nothing,
it answers in a fraction of a second for a fraction of the cost of a chat
model.

Agents use it through the **classify** tool, for decisions they repeat many
times: labelling or triaging a list, checking which state a web page is in,
or filtering inside a script. Volli features can use it too.

In **Settings → Models → Decision model**, choose one of three options:

- **None** (the default). Nothing uses a decision model, and agents do not get
  the classify tool.
- **Local**. A model you run with llama.cpp's `llama-server` on this Mac.
  Enter the server address (for example `http://127.0.0.1:8080`) and, for a
  server that loads several models, the model id. Select **Test** to ask the
  server one question, then **Save**. Only addresses on this Mac are accepted
  (`localhost`, `127.0.0.1` or `[::1]`), so nothing leaves the machine.
- **Cloud**. A classifier from a provider, such as TypeSafe's Jev on
  TypeSafe, OpenRouter, Cloudflare Workers AI, Vercel AI Gateway or OpenCode
  Zen. When you choose one, Volli asks you to allow sending data to it and
  says what is sent. If the provider is not signed in yet, the row says
  **Needs setup**; select **Sign in** and enter the key under
  **Available to connect**, like any other provider.

### What leaves your Mac

A local model sends nothing off your Mac. A cloud model receives whatever is
being classified. For the classify tool, that is whatever the agent passes
it: Session text, tool results and page content. Volli never puts your
provider key in a Session, a prompt or a tool, and no agent can set one.

### Turning it off

Choose **None**. Calls stop immediately, including calls from Sessions that
already have the classify tool: the tool then tells the agent that no
decision model is configured, and the agent decides for itself. A project can
use a different decision model, or turn it off for itself, in
**Configure → Sessions → Chat → Decision model**. A project with its own
choice there keeps it, so to turn decision models off everywhere, also reset
or set to **None** any project that overrides the app-wide setting.

The classify tool is added only to Sessions created while a decision model is
set. Turning one on does not add the tool to Sessions that already exist.
Decision calls are counted in each Session's usage and in `volli cost`.

### Picking models automatically

With a **Cloud** decision model, **Pick models automatically** is a switch
under it, off by default. Turn it on and Volli asks once, saying what is sent:
the first message of a new chat, a delegated task or an Automation run, along
with the models you have set up. From then on, a new Session that was not told
which model to use has one chosen from the models you already set up in
**Settings → Models** (the Session's default and your Fast, Deep, Ticket
Sessions and Board chats rows), each at the reasoning level you gave it.

- It applies to a new chat sent with the default model, to `session_start` and
  `session_delegate` calls that name no model, tier or reasoning level, and to
  Automations that do not pin a Runtime. A model or tier you or an agent name is
  never overridden.
- The choice is made once, when the Session is created. A Session that is
  already running never changes model.
- If the decision model is unavailable, slow or unsure, the Session uses your
  default model, with no message and no delay.
- The Session's model picker says **Auto-picked** with the model and effort,
  and lists the alternatives it passed over, so you can switch to one in a
  press.

Choose a different model or turn the switch off at any time. A project that
has its own Cloud decision model has its own switch in **Configure →
Sessions**.

## Automatic compaction

**Automatic compaction** is on by default. When a Session's conversation nears
its context limit, Volli shortens it automatically. Turn the setting off if
you don't want that. Turning it off does not disable `/compact` or recovery
after a provider rejects a turn because the context is too large.

## Usage readings

Volli shows two kinds of usage:

- **Session usage** totals the model operations recorded for a Session. Volli
  marks the total **Provider-reported**, **Estimated** (priced from its own
  catalog), or **Unverified**. When Volli can price only some of a Session's
  operations, it marks the total as partial. A catalog estimate is an
  estimate, not an invoice.
- **Usage limits** shows the subscription usage windows that supported
  providers report. Open the **Usage limits** control beside `⌘K` to check
  them; they are not in **Settings → Models**.

configuration and the other Settings pages, and [Chats and
