Volli has two structured Session scopes. Both are backed by the Pi Agent
Runtime and persist local history. Their scope determines where they work and
what context they receive.

| Session | Context | Working directory |
| --- | --- | --- |
| **Ticket Session** | One Ticket and its Runtime Brief | That ticket's worktree |
| **Project Session** | The project, without a Ticket | The project's main checkout |

Choose a default model in **Settings → Model Access** before starting either
kind. The model policy is recorded for the Session; Volli does not silently
fall back to a different model or account.

## Ticket worktrees

When a Ticket Session needs isolated repository work, Volli prepares a ticket
worktree on a branch named `volli/<DISPLAY-ID>-<slug>`, for example
`volli/VC-12-mcp-server`. Worktrees live under `~/.volli/worktrees/`.

The project folder you add to Volli remains the main checkout. A ticket's files
and change set come from its worktree, so parallel tickets can make changes on
separate branches.

You can inspect a ticket's branch from a terminal companion:

```sh
volli worktree status VC-12
volli worktree diff VC-12
```

`worktree diff` compares the ticket branch with its base branch. Add
`--working-tree` to see uncommitted changes.

## Durable Session history

A Session is not a terminal pane. Its history stays available when you navigate
away, when an attachment ends, or when you reopen the app. Use the ticket
workspace to return to a Ticket Session and inspect its recorded work.

This separation also makes recovery explicit. A new attachment can reconnect
to an existing Session without inventing a new conversation history.

## Terminal companions

Volli can also open manual terminals and external or bring-your-own TUI
harnesses. Use them when you want a shell or a specific terminal workflow.
They can run in a project or ticket worktree, but they are companions rather
than an alternate structured executor.

The `volli` CLI is available to supported terminal companions over a local Unix
socket. It can inspect ticket context and report work to the app. See the
[CLI reference](/reference/cli/) for its commands.

<Aside type="note">
  A terminal companion does not become a fallback for a structured Session.
  Choose it explicitly, and configure Model Access for Pi-backed execution.
</Aside>

## Change sets and retained worktrees

A ticket's change set includes committed and uncommitted changes relative to
its base branch. Volli reads it from git rather than storing a copy.

Archiving a ticket retains its worktree. You can remove a worktree from the
ticket context menu, or use **Archive & clean** when Volli offers it. A clean
worktree can also be reclaimed after the ticket has spent the configured
retention period in Done with no open pull request and no work running there.
The ticket, branch, commits, and pull-request URL remain.

To remove one yourself after its branch is landed, run:

```sh
git worktree remove ~/.volli/worktrees/<project-dirname>-<short-id>/<TICKET-ID>-<slug>
```
