Use the ticket workspace to inspect a ticket's **Change Set**: the committed
and uncommitted changes in its worktree compared with its base branch. Review
the file diffs before you commit or publish the branch.

To publish a GitHub pull request, the repository needs a GitHub remote and the
GitHub CLI (`gh`) installed and authenticated. In a terminal, use `gh auth
login` if needed. You can inspect and commit locally without creating a PR.

## Inspect the Change Set

1. Open the ticket workspace and select **Diffs** in the rail.
2. Read the changed-file list and its insertion and deletion totals.
3. Select a file to open its diff in a tab. Use **Refresh changes** if you want
   to request a new read.

The **Diffs** page shows the Change Set, not just uncommitted edits. A file
with a local commit can still appear if the commit is not in the base branch.
The worktree footer remains available under each rail page; open it to see the
branch, base, worktree state, and pull-request actions.

## Test the result

Open a [terminal companion](/guides/terminal-companions/) on the ticket and run
the project's relevant tests or build checks. Use the ticket's **Files** rail to
inspect the changed files in context. Opening Diffs does not run checks or
certify the agent's work.

## Commit changes

1. In the worktree footer, open **More repository actions** and choose **Commit**.
2. Enter a **Commit message**.
3. Review **Include unstaged changes**. Clear it if you want the commit to
   include only files you have staged.
4. Confirm **Commit**.

The main repository action can also combine commit and push, with labels such
as **Commit & create draft PR** or **Commit & push updates**. The same commit
confirmation applies. Volli cannot undo a commit for you.

## Push a branch and create a draft PR

When the branch has committed work to publish and no pull request exists,
choose **Push & create draft PR**. If a pull request already exists, the action
can push updates; use **View PR** to open the pull request. A push-only action
publishes commits already on the branch; uncommitted work stays in the
worktree. The commit and push steps are distinct Git operations, even when the
primary action runs both.

Volli pushes the branch with Git and uses `gh` to find or create the draft
pull request. If publishing fails after the commit, the local commit remains;
repair the reported authentication or remote problem, then retry the push.
Volli does not merge the draft pull request for you.

## Bring in base-branch changes

From the ticket's terminal companion, merge the available base ref:

```sh
volli worktree sync VC-12
```

Replace `VC-12` with your ticket's ID. Sync uses refs already on disk; it does
not fetch from the remote or wait for checks. If it reports `conflicted`, read
the listed paths and resolve and commit the merge in the terminal. To abandon
that in-progress merge, use `volli worktree sync VC-12 --abort`.

After your pull request is merged, follow
[Clean up worktrees](/guides/clean-up-worktrees/) to remove checkout state.
