Opening a ticket gives you one working surface for its Ticket Body, Sessions,
files, change set, and properties. The tab strip keeps the surfaces you open;
the right rail helps you move between them.

## Sessions

The **Sessions** rail lists the ticket's durable Session records. Open a record
to return to its history. A Ticket Session carries the ticket's context and
works from that ticket's worktree; it does not become a different Session when
its live runtime attachment changes.

Use the ticket's session controls to start structured work after configuring
**Settings → Model Access**. If you need a shell or an external TUI harness,
open a terminal companion explicitly.

## Files and references

The **Files** rail shows the ticket's file references and its worktree files.
Use `@` in the Ticket Body to add a file reference. A reference resolves in the
ticket's current context, so a file in **Ticket Files** can differ from the same
path in **Project Files**.

**Project Files** read from the main checkout. **Ticket Files** read from the
ticket worktree. Editing one does not edit the other.

## Changes

The **Changes** rail compares the ticket worktree with its base branch. Open a
file to inspect its diff. The change set includes committed and uncommitted
work, so it reflects the branch as it is on disk.

## Properties

Use **Properties** to inspect and edit ticket status, priority, labels, branch,
base branch, worktree location, and pull-request information when present.
Changing status updates the board. Starting structured work is a separate
Session action.

<Aside type="note">
  Worktrees are retained when a ticket is archived. See
  [Sessions and worktrees](/guides/agents-and-worktrees/#change-sets-and-retained-worktrees)
  for safe removal after the branch is landed.
</Aside>
