Signed-out Volli stores projects, tickets, and Session history locally and
needs no Volli account. Local storage does not mean every feature runs offline.

## Invite-only cloud preview

Cloud Workspace data and Session history sync to Volli's cloud backend.
Signing in does not move existing local projects; moving a project is a separate
action that uploads its records, history, agent logs and attachments. Local agent tools can put file contents, code, command
output and secrets into synced history. Read the
[Preview Agreement](https://volli.app/legal/preview/),
[Preview Privacy](https://volli.app/legal/privacy/) and
[subprocessor list](https://volli.app/legal/subprocessors/) before joining.

The preview is free, without an SLA, and may lose or reset data. Keep your own
copies. The preview has no Volli-operated product analytics or crash-reporting
integration. The agent telemetry collector you configure below is separate.

Convex stores account, board and Session records; Cloudflare R2 stores uploaded
history, attachments and move staging; WorkOS handles sign-in; Google Workspace
handles email you send us. Model providers and connected tools receive data at
your direction under their own terms. Subscription logins stay on your machine.

Settings → Account can request account deletion and cancel it within 30 days.
The automatic account purge is not implemented in this preview: that window is
not an erasure deadline. Archiving a cloud project or ticket does not purge it.
Move-upload expiry and backup purge deadlines are not guaranteed. Local profile
backups do not back up live cloud data.

There is no complete self-service cloud export or deletion yet. For a moved
project, **Settings → Volli Cloud → Progress and local copies → Go back to local**
saves a readable cloud export before unlocking its earlier local copy; this is
not a complete backup and keeps the cloud copy. For access, correction, export
or deletion help, email [privacy@volli.app](mailto:privacy@volli.app). Deleting
local app data or uninstalling does not delete cloud data.

## Local storage

| Data | Location |
| --- | --- |
| Database, local history, settings, and Session files | `~/Library/Application Support/Volli Code/` |
| Ticket worktrees | `~/.volli/worktrees/` |
| Main checkout | The repository folder you added as a project |

Removing a project from Volli does not delete its repository folder. Closing a
chat tab does not delete its Session history. Archiving a ticket keeps its
history and branch; worktree cleanup follows separate rules.

The JSON data export omits attachments and transcript files and cannot be
restored. See [Manage local storage](/guides/storage/) before removing data.

## Outbound requests

| Feature | What goes to another service |
| --- | --- |
| Model requests | Conversation context and tool results sent to the provider you select |
| Web search | Query terms sent to the search provider configured in **Settings → Web Search** |
| Web reads and Browser Tabs | Requests to the websites you or a Session open; browser actions can submit information to those sites |
| Remote MCP servers | Tool arguments, which can include paths or file contents, sent to the configured server |
| Git and pull requests | Repository operations and pull-request checks against your configured remotes and GitHub |
| Updates | Requests to check for and download app releases |
| Agent telemetry | Events sent to the collector you configure, when enabled |

The services you connect have their own storage and privacy policies. Check
those policies before sending private repository contents through a model or
a remote tool.

## Local tools

A worktree separates Git changes. It does not sandbox processes. Shell
commands and local MCP servers run on your Mac. A local MCP server runs as
your macOS user and can access the files and network that user can access.

Project authority settings control supported agent operations; they are not an
operating-system sandbox. See [Agent authority](/guides/authority/) for the
coordination permissions and execution boundaries.

## Optional network features

Set **Settings → Web Search → Provider** to **Off** if you do not want the
search tool to use a provider. This does not disable Browser Tabs, web reads,
model requests, or network access from shell commands.

**Settings → Telemetry** is off until you enable it. You supply the collector.
It is separate from the model requests a chat needs to run.

In **Configure → MCP Servers**, select only the tools you intend to use.
Changes apply to new Sessions. A Session keeps the tool list it started with,
so disabling a server does not revoke that list. See
[MCP servers](/guides/mcp-servers/) for transport and deletion limits.
