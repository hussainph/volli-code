Use the installed build's help to check its capabilities. A newer app can have
commands and tools that an older Session has not received.

## Inspect the installed build

```sh
volli help changes
volli help
```

`volli help changes` prints the CLI bundle's source revision and capability
record. When the app is reachable, it also reports the running app version.
The CLI bundle and app version are separate facts.

Inside a Session, `volli help` also lists its recorded tools. A tool described
in the latest docs may be unavailable to that Session. Use the tools it holds,
or start a new Session after configuring the capability you need.

## Existing Sessions and new tools

A Session keeps its original tool record. Reopening it does not replace that
record with the current defaults.

Volli can add eligible capabilities without removing or renaming the tools
already recorded. Additions that change what the model sees wait for a new
context-cache boundary, such as compaction or a model switch. Tools available
only through Code Mode can be announced without changing that cached prefix.
An app update or a settings change does not guarantee an immediate addition.

See [Agent operating model](/reference/agent-operating-model/) for Session
roles and [Code Mode](/guides/code-mode/) for tool routing.
