## A chat cannot start or has stopped

In **Settings → Models**, connect a provider and choose an available default.
See [Models and usage](/guides/models/) for account and tier setup.

If an existing Session has stopped, keep its conversation and follow
[Recover a Session](/guides/recover-session/). The status determines whether to
retry, repair provider access, wait for a reset, or answer a question.

## An Automation does not start automatically

Check all of the conditions for the Trigger:

- For a ticket-enter Trigger, **Automatic triggers** must be on for the Automation on this Mac.
- The destination column must offer the Automation and have it armed, not
  **No Automation**.
- The ticket must make a new **Deliberate move** into the column. Enabling or
  arming a column does not process tickets already there.
- A different Automation can be armed in the column; only one can fire on its
  own.

A switched-off Automation is still available for a manual Run. See
[Run an Automation](/guides/automations/run/) and
[column triggers](/guides/automations/columns/) for the steps.

## A scheduled Automation was skipped

Volli must be open and awake enough to observe the due time. Open the
Automation's **Runs** history and read the **Skipped** reason. **Run now**
starts one current Run; it does not replay every missed occurrence.

## A Run cannot use its Runtime

An exact model pin can become unavailable after it was saved. Repair the
Automation's Runtime in its editor or choose another model. Volli does not
silently fall back to a different model. A Run already in flight can also
block another Run on the same ticket; wait for it to finish or inspect the
existing Session.

## `volli` exits with code 3

The local CLI could not reach the running app.

1. Check that Volli is open.
2. Run `volli identify` from the terminal companion.
3. Check that the terminal has `VOLLI_SOCKET` set.

Volli sets the socket context for terminal companions it starts. A terminal you
open elsewhere may need the CLI installed and connected separately.

## `volli: command not found`

Open **Settings → About** for the install's CLI checks; they run when the pane
opens, and a fault offers **Fix** to regenerate the parts Volli owns, with
**Re-check** to run them again. To see the detected executable and shell
integration, copy the support report from that pane. Terminal companions opened
by the app already receive `volli` on `PATH`.

## A source build cannot load the terminal module

`node-pty` must match Electron's ABI after a dependency install. Follow
[Build from source](/reference/build-from-source/#rebuild-the-terminal-module)
to rebuild it. An install error itself needs the remedy named in its output.

## My ticket worktree is still on disk

Archiving and worktree removal are separate actions. A pinned, dirty, active,
or otherwise ineligible worktree can remain on disk. Follow
[Clean up worktrees](/guides/clean-up-worktrees/) to inspect the reason and
choose a safe removal path.

## A shortcut does nothing

Terminals can claim keystrokes before the app does. Click outside the terminal
companion and try the shortcut again.

Single-letter shortcuts are suppressed while you are typing in a text field,
editor, or dialog.

## The terminal does not follow my app theme

A named theme in your Ghostty configuration takes precedence over Volli's
generated colors. Remove the `theme` key from Ghostty and Volli terminal
settings if you want the terminal to follow the app theme. See
[Theming](/guides/theming/).

## MCP tools do not appear in a chat

A Session keeps the tools it received when it was created. After adding or
enabling tools, create a new Session. Follow [MCP servers](/guides/mcp-servers/)
for discovery failures, unsupported authentication, and deletion limits.

## Where Volli keeps things

See [Local data and network access](/reference/data-and-privacy/) for storage
locations. Removing a project from Volli does not delete its repository folder.
The JSON export is not a restorable backup; see
[Manage local storage](/guides/storage/).

## Report a bug

Include the output of `volli identify` and the steps that led to the problem in
a GitHub issue: [hussainph/volli-code](https://github.com/hussainph/volli-code/issues).
