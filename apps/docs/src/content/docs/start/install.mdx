Volli Code is a local-first macOS workspace for code projects. Install it, pick
a model, and start your first chat.

<Aside type="caution" title="This is an alpha">
  Volli Code is in early alpha. Builds are published as prereleases, features
  move between them, and behavior you depend on can change. Use it on work you
  can afford to have interrupted, and keep your own backups and branches.
</Aside>

## What you need

| | |
| --- | --- |
| **Mac** | Apple silicon (M1 or later). No Intel or universal build yet. |
| **macOS** | 12.0 Monterey or later. |
| **Git** | Installed, with your repositories on disk. |
| **A model** | An account with a model provider, set up on first launch. |

Volli itself needs no account.

## Install it

Download the `.dmg` from [volli.app/download](https://volli.app/download/), drag
**Volli Code** to Applications, and open it.

If macOS blocks the app, the download was damaged. Delete it and download again.

## Updates

The app installs a newer alpha when you quit. To stay on a specific build,
download that release's `.dmg` from
[GitHub Releases](https://github.com/hussainph/volli-code/releases) and replace
the app in Applications.

## First run

<Steps>

1. **Add a project.**

   Select **+** in the project rail and pick a git repository. That folder
   becomes the project's main checkout. Volli derives a ticket prefix from the
   folder name, so a project called `harbor` gets tickets like `HB-1`.

2. **Choose a model.**

   Open **Settings → Model Access**, sign in to your provider, and pick a
   default model. Volli never silently switches to a different one.

3. **Start a chat.**

   Press **Chat**. On **Home**, that starts a project chat working from your
   main checkout. Inside a ticket, it starts a ticket chat carrying that
   ticket's body and scoped context.

</Steps>

Continue with the [Quickstart](/start/quickstart/) for the full path from an
empty board to a reviewed change.

## Chats and terminals

A **chat** is Volli's structured session, running on the model you picked in
Model Access. It's what **Chat** starts.

A **terminal** is a manual companion: a shell in the ticket's worktree where you
drive Claude Code, Codex, OpenCode, or your own TUI. It's under the caret beside
**Chat**, and you ask for it explicitly. Volli never opens one as a fallback.

## The `volli` CLI

Terminals Volli opens already have the `volli` command on `PATH`. To see what a
terminal is attached to:

```sh
volli identify
```

Check the installation or run Doctor in **Settings → CLI**. Full command set in
the [CLI reference](/reference/cli/).

## Where your data lives

- Projects, tickets, and history: `~/Library/Application Support/Volli Code/`
- Ticket worktrees: `~/.volli/worktrees/`
- Chat transcripts: on disk, indexed locally

Model requests go to the provider you selected. Nothing else leaves your
machine. Removing a project from Volli does not delete its folder.

## Uninstall

<Steps>

1. Quit Volli Code and drag it from Applications to the Trash.

2. Remove its application data:

   ```sh
   rm -rf ~/Library/Application\ Support/Volli\ Code
   ```

3. Remove any worktrees Volli created. These are git worktrees inside your own
   repositories, so remove them through git rather than deleting the folder:

   ```sh
   ls ~/.volli/worktrees/
   ```

   For each one you no longer want, run `git worktree remove <path>` from the
   repository it belongs to. Uninstalling does not touch your project folders.

</Steps>

## Build from source

You can also run the development build. You need a Mac, [git](https://git-scm.com),
Node `^24.13.0`, and pnpm `11.10.0`. The repository pins both versions.

<Steps>

1. Clone the repository and install dependencies.

   ```sh
   git clone https://github.com/hussainph/volli-code.git
   cd volli-code
   pnpm install
   ```

2. Start the development app.

   ```sh
   pnpm dev
   ```

   This runs the renderer with hot reload and relaunches Electron after main
   process changes.

3. To run a built copy instead:

   ```sh
   pnpm run build
   pnpm start
   ```

</Steps>

<Aside type="tip">
  If a native dependency fails to build, run `pnpm -C apps/desktop run
  rebuild:native`. This rebuilds the native modules against Electron's ABI.
</Aside>
