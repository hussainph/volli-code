These terms have the same meaning across the app and its documentation.

## Planning

**Project.** A tracked codebase folder. Removing it from Volli does not remove
the folder from disk.

**Home.** The project's tabbed workspace, and where a project opens. Its first
tab is the Board and cannot be closed; project chats and Project Files open as
tabs beside it. Chats live here rather than on a separate Sessions page.

**Ticket.** A board card that holds a title, status, and Ticket Body. A ticket
can provide the context for a Ticket Session and its worktree.

**Ticket Body.** The ticket's canonical Markdown scope and starting instruction.
It is part of the ticket record, not a repository file.

**Ticket workspace.** The expanded working surface for one ticket. Its main
tabs hold the Ticket Body, Sessions, files, and diffs. The right rail groups
repository state, properties, and Sessions under Now, with separate Diffs and
Files views.

**Display ID.** The project-local handle shown to people, such as `VC-12`.

## Sessions

**Session.** A durable identity and locally ordered history for an agentic
conversation. It exists before a runtime attaches and remains openable after
its attachment, turn, or run ends. A chat and a terminal are both Sessions.

**Chat.** The structured Session, and what **Chat** starts. It runs on the
Pi-backed Agent Runtime using the model you chose in Model Access, and Volli
renders its turns, tool steps, and questions in the product. This is the
default way work happens.

**Ticket chat.** A chat scoped to one ticket. It carries that ticket's Body and
resolved context, and works in the ticket's worktree. Its runtime receives a
generated Runtime Brief from the ticket.

**Project chat.** A chat scoped to the project's main checkout, started from
Home. It has no ticket context, and it can create and edit tickets. Start here
when the work is not yet shaped.

**Model Access.** The accounts, subscriptions, credentials, and models that
Volli can truthfully use. You select a default model here before opening a
structured Session. Credentials do not enter Session history.

**Terminal companion.** A manual terminal or external TUI harness you open for
work in a project or worktree: Claude Code, Codex, OpenCode, or your own. You
ask for it explicitly from the caret beside **Chat**. It is separate from
structured execution, and Volli never opens one as a fallback when a chat
fails.

## Git work

**Ticket worktree.** An isolated checkout for a ticket. Volli creates its
branch as `volli/<DISPLAY-ID>-<slug>` and stores the checkout under
`~/.volli/worktrees/`. A worktree is disposable checkout state. Volli can
recreate it from the retained branch after cleanup.

**Main checkout.** The repository folder you added as a project.

**Change set.** Committed and uncommitted work in a ticket worktree, measured
against its base branch.

**Ticket Files.** The files in a ticket's worktree.

**Project Files.** The files in the main checkout.

## History and control

**Session Event.** An immutable fact in a Session's local history, such as a
message, command outcome, interaction, attachment outcome, or recovery signal.

**Command.** Explicit user intent recorded before the runtime is asked to act.

**Receipt.** The recorded outcome of a Command: accepted, rejected, completed,
or unreconciled.

**Attention.** A reconstructed view that shows when a Session needs recovery
or input. It is derived from Session history rather than a source of truth.

## In development

**Automations** are in development. They will be saved board triggers that open
Sessions with instructions, a runtime, and recorded outcomes. They are not
available to configure yet.
