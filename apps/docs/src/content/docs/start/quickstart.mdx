By the end of this page you will have added a project, turned a loose idea into
tickets with a chat, run one ticket in its own isolated worktree, and read the
change it produced.

You need Volli [installed](/start/install/), a git repository on disk, and about
fifteen minutes.

## 1. Meet Home

A project opens on **Home**, a tabbed workspace. The first tab is the **Board**
and it never closes; chats and files open as tabs beside it.

![Home's permanent Board tab for a project named voltaic. Five columns hold tickets, and the Chat control is available at the right of the tab strip.](../../../assets/screenshots/board.png)

<Aside type="note" title="If you haven't added a project yet">
  Select **+** in the project rail and choose a git repository. That folder is
  the project's main checkout. Volli derives a ticket prefix from the folder
  name. A folder called `harbor` gives you `HB-1`, `HB-2`, and so on.
</Aside>

## 2. Start a project chat

<Steps>

1. **Press Chat** on Home's tab strip.

   This starts a *project chat*, working from your main checkout.

2. **Describe what you want, loosely.**

   A project chat is the right place to be vague:

   > We need to move billing off the nightly job and onto Stripe webhooks. Break
   > that into tickets for me.

3. **Switch to the Board tab.**

   A project chat can create and edit tickets. Watch them land.

</Steps>

<Aside type="tip">
  The difference between the two is scope. A project chat sees your main checkout
  and the whole board, which is what you want when the work isn't shaped yet. A
  ticket chat sees one ticket and works in that ticket's own checkout.
</Aside>

## 3. Write the ticket body

Open a ticket from the board.

The first tab is its **body**. Write what should change, what must not, and how
you will judge the result.

This is the starting context for every chat on the ticket. Anything vague here
comes back as a vague change later.

![A ticket workspace for VLT-14. The Ticket Body holds the scope, the right rail shows the ticket's worktree and review state, and Chat is available at the top right.](../../../assets/screenshots/ticket-workspace.png)

## 4. Start a ticket chat

<Steps>

1. **Press Chat inside the ticket.**

   Volli prepares the ticket's isolated git worktree and starts a chat that
   already carries the ticket body and the ticket's resolved context.

2. **Watch it work, and answer it.**

   When it needs a decision, it asks instead of guessing. Interrupt it whenever
   you want.

3. **Leave and come back.**

   Close the tab or quit the app. Reopen the chat from the ticket's **Chats**
   rail, the sidebar, or <kbd>⌘K</kbd>, with its history intact.

</Steps>

<Aside type="note" title="Moving a ticket does not start anything">
  Dragging a ticket to **Doing** organizes your board. It does not start a chat.
  Starting work is always an explicit press of **Chat**.
</Aside>

## 5. Read what changed

The ticket worked in its own git worktree, on its own branch, beside your main
checkout rather than in it.

- **Changes** shows the change set against the base branch.
- **Files** opens the ticket's files as they are in the worktree.

Read the change yourself. Volli shows you what happened; it does not certify the
work is correct or run your tests for you.

## 6. Deliver it

Commit, push, and open a pull request from the ticket's repository summary, then
move the ticket. Clean up its worktree from the same place when you're done.

## Using a terminal instead

To drive a CLI yourself, open the caret beside **Chat** and choose **Terminal**.
You get a shell in the ticket's worktree for Claude Code, Codex, OpenCode, or
your own TUI. Volli never opens one as a fallback.
