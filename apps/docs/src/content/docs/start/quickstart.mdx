Start a Ticket Session that has the ticket's scope and an isolated git worktree.
You need Volli [running](/start/install/), a git repository on disk, and a
default model selected in **Settings → Model Access**.

<Steps>

1. **Add a project.**

   Select **+** in the project rail and choose a repository. That folder is
   the project's main checkout. Volli derives a display-ID prefix from its
   name, such as `VC-12`.

2. **Create a ticket.**

   Give the ticket a short title and a body. The body is the ticket's canonical
   Markdown scope. State what should change and how you will judge the result.

3. **Open the ticket workspace.**

   Create the ticket, then open it from the board. Move it to **Doing** when
   that is the right state for the work. The board state and Session creation
   are separate actions.

4. **Start a Ticket Session.**

   Select **New chat** in the ticket workspace. Volli prepares the ticket
   worktree and starts a Ticket Session through the Pi-backed Agent Runtime.
   The Session receives the Ticket Body and the ticket's resolved context.

5. **Work with the Session.**

   Read the Session history, answer its questions, and inspect the ticket's
   files and change set from the workspace. A Ticket Session remains available
   after its live attachment stops, so you can reopen its history later.

6. **Review the branch.**

   Use the ticket's **Changes** view to compare its worktree with the base
   branch. Move the ticket when you are ready; the board records the change.

</Steps>

<Aside type="note">
  Moving a ticket to **Doing** organizes work on the board. It does not choose
  a model or start structured execution. Start a Ticket Session from the ticket
  workflow after Model Access is configured.
</Aside>

## Use a terminal when you need one

Manual terminals and external or bring-your-own TUI harnesses are terminal
companions. They can work in the ticket's worktree, but they are separate from
the structured Pi-backed Ticket Session. Choose the companion explicitly; it
does not become a Session fallback.
