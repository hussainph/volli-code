**0.2.0 — September 29, 2026.**

0.2 adds **Automations**, lets agents drive **Browser Tabs** you can watch and
take over, and shows what each chat is holding in the **Activity Island**. It
also adds split view, MCP servers, model tiers for delegated work, provider
usage limits, and a new terminal engine.

Update from **Settings → Updates**, or download the build from
[volli.app/download](https://volli.app/download/).

<Aside type="caution" title="Alpha">
  Volli is in early alpha, for Apple silicon Macs. Features move between
  builds.
</Aside>

## Automations

An **Automation** is a saved, named way to start work. It keeps its
**Instructions**, **Trigger**, and **Runtime** together, so you can start the
same setup by hand, when a ticket enters a board column, or on a schedule.

- **Instructions** are the first message of the fresh **Session** a Run opens.
- **Trigger** is **Only when I run it**, **Ticket enters**, or **On a
  schedule**. Every Automation can also be run by hand.
- **Runtime** is the model policy: a project default, a named default tier, or
  an exact model and reasoning level.

Create and edit Automations on the **Automations** page. Run a saved one from
that page, a ticket's **Automations** section, a board card's context menu, or
the command palette. Automatic starts are off until you turn on **Enabled** for
this Mac and, for a column Trigger, arm the column. Only a **Deliberate move**
into an armed column starts a Run, after a short delay you can **Cancel**.
Schedules use presets and need Volli to be open; a missed due time is recorded
as **Skipped**.

Each Run opens a fresh Session and records the model and reasoning it resolved.
See [Automations](/guides/automations/) for the full behavior.

## Browser Tabs

A **Browser Tab** is a web page inside the workspace. Open one yourself from the
**Chat** menu's **Browser** item, or let a chat open one to check the page it is
building.

- A tab a Session opens starts hidden. It appears as a card in that chat, and
  you choose whether to show it above the composer or open it as a tab.
- While a Session drives a tab, the **Session cursor** shows where its input
  goes, in that Session's colour and with its name.
- Only one party drives a tab at a time. Use **Take over**, **Ask to leave**,
  or **Hand back** to change who has it. Your own input into the page always
  goes through.
- A Session sees your tabs and its own, not the tabs of other Sessions.

What a page shows is treated as untrusted content, and tabs run apart from the
app itself.

## The Activity Island

The **Activity Island** is a pill above a chat's composer that shows what that
Session is holding besides the conversation:

- **Browser Tabs** it opened.
- **Subagents** it started. A chat can delegate work to child Sessions. Hover a
  subagent to see its progress, peek at it, open it as a tab, or stop it.
  Subagents do not appear as separate rows in Session lists.
- **Plan**: the checklist the agent keeps for multi-step work, shown as done
  over total.
- **Background shells**: long-running commands such as a dev server or a watch
  build, which run beside the turn instead of blocking it. Open one to read its
  output. Background shells stop when the Session's connection ends and do not
  survive a relaunch.

The island appears only when there is something to show. The ticket's **Now**
rail keeps what is true of the whole ticket.

## Split view

**Home** and the ticket workspace can each be split into **Panes**. Drag a tab,
Session, or file to the right or bottom edge of a pane to split there, or use
`⌘\` to split right and `⇧⌘\` to split down. Each surface keeps its own
split, and tabs do not move between the two. See
[Keyboard shortcuts](/reference/keyboard-shortcuts/#panes).

## MCP servers

**Configure → MCP Servers** adds Model Context Protocol servers to a project,
over stdio or streamable HTTP, and chooses which of their tools chats may use.
MCP tools run through Volli like its other tools and appear in Session history.
A change applies to new Sessions; a running Session keeps the tools it started
with.

## Model tiers for delegated work

**Settings → Models** adds three default tiers by kind of work: **Fast** for
quick, low-cost tasks, **Deep** for complex reasoning, planning, and review, and
**Visual** for images, screenshots, and pages. An unset tier uses the **Ticket
Sessions** default. Model pickers list the defaults you set, and an agent that
starts another Session or delegates to a subagent can ask for a tier by name.
An Automation's Runtime can name a tier too.

A subagent that names neither a model nor a tier runs on its parent's model.

## Usage limits

The usage-limits icon beside the `⌘K` search opens a popover with how much of
each subscription window you have used and when it resets. It covers supported
provider subscriptions: Anthropic (Claude Pro/Max), OpenAI Codex, GitHub
Copilot, Kimi Code, OpenCode Go, xAI, and Z.ai. Readings are live and are not
stored in Session history.

## Chat and terminal

- **Images render inline** in chats, ticket bodies, comments, and queued
  messages. Remote image URLs are not loaded; a refused image shows its reason
  instead of a blank space.
- **The terminal uses xterm.js.** Terminals keep taking their appearance from
  your Ghostty configuration. Output is readable by VoiceOver, and
  **Control+Shift+M** lets **Tab** move focus out of a terminal. See
  [Keyboard shortcuts](/reference/keyboard-shortcuts/#terminal).
- **Recovery after a crash.** A Session whose turn was running when Volli quit
  unexpectedly can be resumed, and a message you send to a disconnected
  Session reconnects it instead of waiting in the queue.

## Performance

Board columns render only the cards near the visible area, long chat
transcripts load earlier messages on request with **Show earlier**, and opening
a ticket makes fewer reads. Large boards, long chats, and many concurrent
Sessions stay more responsive.
